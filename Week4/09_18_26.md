## 2. System Diagram: How It Works

*This diagram shows how the system functions (inputs, processing, decisions, outputs), not what the interface looks like.*

<!-- TODO: export slide 5 of the deck as a PNG to Week4/assets/09-18/slide-05.png, then uncomment -->
<!-- ![Reliable Peer system diagram](assets/09-18/slide-05.png) -->

**Walkthrough of the diagram:**
1. **Input:** The student fills in an initial ask, desired output, symptoms/reason, logistics, and one of four tone modes.
2. **Processing:** An Express server (`server.ts`, `/api` endpoint) assembles the prompt from those inputs plus the role card constraints.
3. **Decision / logic:** The role card (9-field system instructions plus a knowledge base covering Hugh Dubberly, the MDes program, Tang Center policy, and Jacobs Hall studio culture) drives a four-stage loop: suggest → diagnose → clarify → offer alternative. Gemini (`@google/genai`) returns structured output for each stage.
4. **Output:** Peer guidance, a drafted letter, a policy check, and one-click edits.
5. **Feedback loop (if any):** The student adjusts the draft with one-click edits. A rule-compliant fallback advisor runs when no API key is present, so the guardrails hold offline.

### Current system card (v0.2)
- **Purpose:** Help classmates with school questions. Informational, not conversational.
- **Intended users:** MDes classmates dealing with absences, medical policy, and studio logistics.
- **How it works:** A four-stage loop (suggest → diagnose → clarify → offer alternative). Behavioral rules: high-level, short, single paragraph, casual tone, first names in the body, lead with empathy, phrase advice as "I would…", logistics only after acknowledgement.
- **Known limitations:** Still sounds like software. Rules get over-interpreted (empathy first even when asked to just write the message). The form-driven flow is not conversational, and the agent's reasoning is not visible behind the GUI.
- **Risks & mitigations:** Does not fabricate, does not over-sympathize, does not dump detail (all in the "does not do" field). The policy check and fallback advisor keep guardrails in place. TODO: risk of giving wrong medical-policy information.
